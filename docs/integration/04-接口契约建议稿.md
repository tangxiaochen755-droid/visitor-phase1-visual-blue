# 接口契约建议稿

> 本文件用于前后端第一次接口评审。除引用一期范围和已生效决策的业务规则外，URL、方法、字段名、状态码、鉴权令牌、幂等、并发和消息实现均为研发建议，须在 OpenAPI/Apifox 或技术设计中确认后冻结。

## 1. 通用约定

- 基础路径建议：`/api/v1`；JSON 使用 UTF-8、字段使用 `camelCase`。
- H5/后台：`Authorization: Bearer <token>`；服务端从令牌获取 `tenantId`、主体和数据范围。
- 设备端：设备凭证 + `X-Device-Code`，不得使用人员 Token。
- 创建申请、审核、撤销、终止、扫码均携带 `Idempotency-Key`。
- 写操作携带 `version` 或 `If-Match`，状态不一致返回 409。
- 列表统一 `pageNo`、`pageSize`，响应返回 `total`、`items`。

统一响应建议：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "requestId": "req_01J...",
  "serverTime": "2026-08-10T14:30:00+08:00"
}
```

## 3. 创建申请请求示例

```json
{
  "visitType": "SINGLE",
  "hostEmployeeId": "emp_001",
  "visitor": {
    "name": "张晨",
    "mobile": "13800006201",
    "company": "上海远航科技",
    "idCardNo": "加密传输并脱敏存储"
  },
  "schedule": {
    "visitDate": "2026-08-12",
    "startTime": "09:00",
    "endTime": "11:00"
  },
  "purposeId": "purpose_business",
  "purposeName": "商务洽谈",
  "otherPurpose": null,
  "companions": [],
  "vehicles": [{"plateNo": "沪A12345"}],
  "remark": ""
}
```

响应至少返回：`id`、`applicationNo`、`visitType`、`source`、`status`、`accountBindingStatus`、`version`、`createdAt`。通行点由服务端依据被访人部门生成，不接受前端越权指定。

`purposeName` 作为提交时名称快照保存；`purposeId` 对应“其他”时 `otherPurpose` 必填。配置项被改名、停用或删除后不得回写历史申请。

长期终止响应需返回最终状态：无未闭合批次时为 `TERMINATED`；仍有访客在场时为 `PENDING_TERMINATION`。待终止期间新的进入核验必须失败，当前未闭合批次的出访仍可完成，出访成功后申请转为 `TERMINATED`。

单次拜访在预约结束时间到达后仍处于来访中时，由服务端任务或等效机制自动结束。申请或批次详情需返回 `endReason`，至少区分出访码结束与超时自动结束；自动结束不应伪造扫码离开事件，具体任务实现不由产品文档指定。

## 4. 审核请求示例

```json
{
  "decision": "APPROVE",
  "reason": null,
  "version": 3
}
```

拒绝时 `reason` 必填；响应返回最新 `status`、`version`、授权有效期和短信任务状态，不直接返回数据库字段。

批量审核请求建议：

```json
{
  "applicationIds": ["app_001", "app_002"],
  "decision": "REJECT",
  "reason": "来访时间与接待安排冲突"
}
```

`decision=REJECT` 时 `reason` 必填，且作为统一理由写入本次成功拒绝的全部记录；`decision=APPROVE` 时不需要理由。响应应逐条返回申请 ID、处理结果、最新状态及失败原因，禁止因一条失败回滚其他已成功记录。

## 5. 设备核验请求示例

```json
{
  "qrPayload": "opaque-signed-token",
  "direction": "ENTRY",
  "occurredAt": "2026-08-10T09:26:18+08:00",
  "requestId": "device-BG-N-01-000012"
}
```

二维码建议为服务端签名的不透明短时载荷，不能包含可篡改的访客身份证号、手机号等明文敏感信息。成功响应仅返回现场核验所需的姓名脱敏摘要、被访人、通行点、结果和事件编号。

## 6. 错误码建议

| HTTP | code | 场景 | 前端处理 |
|---:|---|---|---|
| 400 | `VALIDATION_ERROR` | 字段缺失、日期或车辆格式错误 | 定位字段并显示服务端消息 |
| 401 | `UNAUTHENTICATED` | Token 失效 | 清理登录态并重新登录 |
| 403 | `FORBIDDEN` | 无权限或数据越界 | 提示无权限，禁止重试写操作 |
| 404 | `NOT_FOUND` | 资源不存在或不在数据范围 | 统一按不存在处理，避免泄露 |
| 409 | `STATE_CONFLICT` | 已审核、已扫码、版本冲突 | 刷新详情和可用动作 |
| 409 | `DUPLICATE_REQUEST` | 重复提交或重复扫码 | 展示第一次处理结果 |
| 422 | `CODE_EXPIRED` / `CODE_USED` | 二维码过期/已使用 | 设备展示明确失败原因 |
| 422 | `ACCESS_POINT_DENIED` | 非授权通行点 | 设备拒绝通行 |
| 422 | `DEVICE_DISABLED` / `DEVICE_OFFLINE` | 设备不可用 | 停止扫码并提示管理员 |
| 429 | `RATE_LIMITED` | 验证码/登录频控 | 展示剩余等待时间 |
| 500 | `INTERNAL_ERROR` | 未知错误 | 展示 requestId 供排查 |

## 7. 安全与审计验收

- 手机号、证件号、二维码载荷在日志中脱敏；密码和验证码永不记录。
- 同一资源跨租户 ID 猜测必须返回 404/403，且不得泄露资源摘要。
- 审核、撤销、终止、异常结束、账号启停、设备绑定均记录操作者、时间、前后状态、原因和 requestId。
- Token、设备凭证、短信验证码均配置有效期、频控和吊销机制。
