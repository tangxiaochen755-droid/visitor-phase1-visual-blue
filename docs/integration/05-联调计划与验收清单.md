# 联调计划与验收清单

## 1. 推荐联调顺序

```mermaid
flowchart LR
  A[规则/枚举冻结] --> B[OpenAPI与Mock]
  B --> C[登录与租户上下文]
  C --> D[主数据与动态配置]
  D --> E[自主申请与审批]
  E --> F[代申请与账号补绑]
  F --> G[设备绑定与扫码]
  G --> H[记录查询与短信]
  H --> I[异常/并发/越权测试]
  I --> J[回归与发布评审]
```

## 2. 阶段交付和准入条件

| 阶段 | 前端交付 | 后端交付 | 测试/产品准入 |
|---|---|---|---|
| 规则冻结 | 页面字段、动作与状态展示清单 | 状态转换表、权限算法 | 产品签字确认枚举与待确认项 |
| 契约冻结 | 请求/响应类型、Mock 接入 | OpenAPI、错误码、示例 | 契约检查通过，无同名异义字段 |
| 核心联调 | 登录、申请、审批、列表详情 | 鉴权、申请状态处理、短信发送记录 | 单次/长期主链路通过 |
| 设备联调 | 设备结果页与错误态 | 设备凭证、原子核验、事件写入 | 重复扫码、错误点位、离线设备通过 |
| 回归发布 | 构建版本、埋点/日志 requestId | 数据库版本、部署版本、回滚方案 | P0/P1 缺陷清零，发布清单签字 |

## 3. 联调环境数据

至少准备：

- 2 个租户，用于跨租户越权测试；
- 每租户 1 个企业管理员、1 个部门负责人、1 个场所管理员；
- 2 个部门、2 个场所、3 个通行点；
- 启用/禁用员工各 1 名；已注册/未注册手机号访客各 1 个；
- 在线启用、离线启用、在线禁用、未绑定设备各 1 台；
- 单次和长期申请的每个状态各至少 1 条。

测试凭证必须通过安全渠道交付，不写入本仓库。

## 4. 主流程验收

- [ ] 访客可用密码或验证码登录；被访人登录方式遵循租户开户配置。
- [ ] 自主申请只可选择启用且可作为被访人的员工。
- [ ] 申请自动继承被访人部门的多个拜访通行点。
- [ ] 单次审核通过进入待来访，长期审核通过进入生效中。
- [ ] 拒绝原因必填，访客可在记录中看到审核失败及原因。
- [ ] 来访目的来自租户启用配置；选择“其他”时具体目的必填，历史记录保留名称快照。
- [ ] 被访人申请记录默认展示待审核；批量审核支持批量通过和批量拒绝，逐条返回成功或失败结果，不因一条失败回滚或重复处理其余记录。
- [ ] 批量拒绝必须填写一个统一理由；本次成功拒绝的全部记录保存并展示同一理由，理由为空时不得提交。
- [ ] 状态标签和拜访形式标签显示各自数量，组合筛选结果与数量一致。
- [ ] 代申请记录通过文字和图标明确提示，不仅依赖颜色区分。
- [ ] 代申请无需访客确认，按拜访形式直接进入待来访/生效中。
- [ ] 已注册手机号即时绑定；未注册手机号标记待绑定，注册后自动补绑且历史不变。
- [ ] 单次进入、离开各产生一条独立成功事件，结束后不可重复使用码。
- [ ] 单次来访中使用出访码后正常结束；未出访且到达预约结束时间时自动结束，两种结束原因可区分，自动结束不伪造扫码离开事件。
- [ ] 长期申请在有效期内始终保持生效中；每次进入/离开只改变独立访问批次，离开后批次已结束。
- [ ] 申请记录、访问记录、后台详情对同一状态和字段显示一致。

## 5. 异常与边界验收

- [ ] 重复点击提交只创建一个申请。
- [ ] 两人同时审核，仅第一笔成功，另一笔收到状态冲突并刷新。
- [ ] 批量审核中部分记录已被他人处理时，仅冲突记录失败，其余仍处于待审核的记录继续按所选动作处理。
- [ ] 同一二维码重复扫码只写一条成功事件。
- [ ] 过期、已用、非授权通行点、设备禁用、设备离线均拒绝核验。
- [ ] 进入成功但短信失败时，通行业务不回滚，短信记录显示失败。
- [ ] 代申请发生首次通行后不可撤销；长期拜访终止时无人仍在场则立即已终止，有人在场则先待终止、拒绝新进入并在出访后转为已终止。
- [ ] 单次超时自动结束与同一时刻出访扫码并发时只产生一个有效结束结果，不重复关闭批次。
- [ ] 员工禁用后不可登录，也不可被新申请选择；历史记录仍可追溯。
- [ ] 手机号换绑不改变访客/员工身份编号和历史归属。
- [ ] 超期任务重复执行不产生重复审计或非法状态转换。

## 6. 权限与安全验收

- [ ] 访客只能查看本人申请、二维码和通行事件。
- [ ] 被访人只能处理本人相关申请，不能通过修改 ID 访问他人数据。
- [ ] 部门负责人和场所管理员的列表、详情、导出、写操作均遵循数据范围。
- [ ] 租户 A 的 Token 不能访问租户 B 的任意资源。
- [ ] 设备只能核验绑定通行点的授权，不能调用人员后台接口。
- [ ] 日志、短信记录和错误信息不泄露完整手机号、证件号、验证码或二维码载荷。

## 7. 待产品/研发共同确认

| 编号 | 问题 | 建议默认值 | 负责人 |
|---|---|---|---|
| Q1 | 部门负责人范围是否包含全部下级部门 | 默认仅本部门；需显式配置是否含下级 | 产品 |
| Q2 | 场所管理员是否有审核和代申请权限 | 默认只读场所相关业务，另授权限才可操作 | 产品/后端 |
| Q3 | 后续是否扩展代申请二次审批 | 不纳入当前一期；如扩展需另行设计 | 产品 |
| Q5 | 短信自动重试次数与补发权限 | 建议指数退避 3 次，后台可追溯 | 后端/运维 |
| Q6 | 二维码刷新周期与离线容忍 | 建议短时签名码，设备在线核验 | 安全/后端 |
| Q7 | 失败核验是否单独落审计表 | 建议落安全日志，不计入成功通行事件 | 后端/测试 |
