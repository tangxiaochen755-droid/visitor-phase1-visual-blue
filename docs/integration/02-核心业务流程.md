# 核心业务流程

## 1. 登录与租户隔离

```mermaid
sequenceDiagram
  participant U as 用户/设备
  participant FE as 前端
  participant API as 后端
  participant AUTH as 鉴权与租户上下文
  U->>FE: 手机号密码/验证码，或设备编码
  FE->>API: 登录或设备绑定
  API->>AUTH: 校验账号状态、租户期限、角色/设备状态
  alt 校验成功
    AUTH-->>API: tenantId + subjectId + roles/scopes
    API-->>FE: accessToken + 用户摘要/设备绑定信息
    FE-->>U: 进入对应端
  else 校验失败
    API-->>FE: 业务错误码
    FE-->>U: 明确提示，不进入业务页
  end
```

## 2. 访客自主申请与审批

```mermaid
sequenceDiagram
  participant V as 访客
  participant FE as 访客H5
  participant API as 后端
  participant H as 被访人
  participant SMS as 短信服务
  V->>FE: 选择被访人并填写申请
  FE->>API: 提交申请 + Idempotency-Key
  API->>API: 校验访客、员工启用、租户规则、日期/车辆
  API->>API: 继承被访人部门的拜访通行点
  API-->>FE: 创建成功，状态=待审核
  API->>SMS: 发送待审核提醒给被访人
  H->>API: 审核通过或拒绝
  alt 审核通过
    API->>API: 审核状态=审核通过；来访状态=待来访；生成通行授权
    API->>SMS: 通知访客审核通过
  else 审核拒绝
    API->>API: 审核状态=审核拒绝，来访状态为空，保存必填原因
    API->>SMS: 通知访客拒绝原因
  end
```

### 批量审核

```mermaid
flowchart TD
  A[进入批量审核模式] --> B[勾选待审核记录]
  B --> C{选择处理动作}
  C -- 批量通过 --> D[二次确认]
  C -- 批量拒绝 --> E[填写统一拒绝理由]
  E --> F{理由是否为空?}
  F -- 是 --> E
  F -- 否 --> D
  D --> G[后端逐条校验权限和当前状态]
  G --> H[逐条返回成功或失败结果]
  H --> I[通过记录生成授权<br/>拒绝记录保存同一理由并通知访客]
```

同一次批量拒绝只接受一个拒绝理由，并应用于本次勾选的全部记录；不支持逐条填写不同理由。单条处理失败不得回滚其他已成功记录。

## 3. 被访人代申请与账号自动绑定

```mermaid
flowchart TD
  A[被访人填写访客手机号及申请] --> B{业务校验通过?}
  B -- 否 --> X[返回字段/规则错误]
  B -- 是 --> C{本租户存在该手机号访客账号?}
  C -- 是 --> D[绑定 visitorAccountId]
  C -- 否 --> E[accountBindingStatus=待绑定]
  D --> F{拜访形式}
  E --> F
  F -- 单次 --> G[直接生效：待来访]
  F -- 长期拜访 --> H[审核通过 / 待来访]
  G --> I[生成授权并发送短信]
  H --> I
  J[访客以后用同手机号注册] --> K[后端查找待绑定申请]
  K --> L[自动补绑账号ID]
  L --> M[历史申请与通行事件保持不变]
```

代申请无访客确认节点。首次通行前允许发起人撤销；长期拜访允许提前终止剩余授权。

## 4. 扫码进入与离开

```mermaid
sequenceDiagram
  participant D as 扫码设备
  participant API as 后端
  participant A as 申请/授权
  participant X as 通行事件
  D->>API: 二维码 + 设备编码 + 进出方向
  API->>API: 校验设备绑定、启用、在线、租户和通行点
  API->>A: 校验码类型、有效期、使用次数、当前状态、授权通行点
  alt 核验成功
    API->>X: 新增一条进入或离开事件
    API->>A: 原子更新申请/访问批次状态
    API-->>D: 成功 + 访客最小展示信息
  else 核验失败
    API->>X: 可选记录失败核验日志，不写成功通行事件
    API-->>D: 失败原因（过期/已用/无权限/设备异常）
  end
```

## 5. 撤销与提前终止

```mermaid
flowchart LR
  A[代申请] --> B{是否已首次通行?}
  B -- 否 --> C[发起人申请撤销]
  B -- 是 --> D[不允许撤销]
  C --> E[服务端校验当前状态]
  E --> F[状态=已撤销]
  F --> G[所有未用二维码/授权作废]
  G --> H[保留申请与审计记录并短信通知]
  I[长期拜访：审核通过 / 待来访或来访中] --> J[发起人提前终止]
  J --> K{是否存在未闭合访问批次?}
  K -- 否 --> L[申请状态=已终止]
  K -- 是 --> M[申请状态=待终止并禁止再次进入]
  M --> N[当前在场访客使用出访码]
  N --> L
  L --> O[剩余授权作废，历史通行保留]
```

## 6. 单次拜访结束

```mermaid
flowchart TD
  A[单次拜访来访中] --> B{先发生哪一项?}
  B -- 使用出访码 --> C[写入离开事件]
  C --> D[来访状态=来访结束<br/>结束原因=出访码]
  B -- 到达预约结束时间 --> E[系统自动结束未闭合访问批次<br/>不伪造扫码离开事件]
  E --> F[来访状态=来访结束<br/>结束原因=超时自动结束]
  D --> G[后续出访码不可重复处理]
  F --> G
```

## 7. 短信结果边界

已确认规则：短信发送失败不得回滚已成功的申请、审核或通行业务；系统保留发送失败状态供后台追溯。异步方式、事务消息/Outbox、自动重试次数、服务商和人工补发均属于研发方案或待确认项，不在当前一期产品规则中指定。
