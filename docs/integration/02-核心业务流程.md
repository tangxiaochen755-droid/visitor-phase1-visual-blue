# 核心业务流程

## 1. 登录与租户隔离

```mermaid
sequenceDiagram
  participant U as 用户/设备
  participant FE as 前端
  participant API as 后端
  participant AUTH as 鉴权与租户上下文
  U->>FE: 手机号密码/验证码，或设备编码
  FE->>API: 登录或设备绑定
  API->>AUTH: 校验账号状态、租户期限、角色/设备状态
  alt 校验成功
    AUTH-->>API: tenantId + subjectId + roles/scopes
    API-->>FE: accessToken + 用户摘要/设备绑定信息
    FE-->>U: 进入对应端
  else 校验失败
    API-->>FE: 业务错误码
    FE-->>U: 明确提示，不进入业务页
  end
```

## 2. 访客自主申请与审批

```mermaid
sequenceDiagram
  participant V as 访客
  participant FE as 访客H5
  participant API as 后端
  participant H as 被访人
  participant SMS as 短信服务
  V->>FE: 选择被访人并填写申请
  FE->>API: 提交申请 + Idempotency-Key
  API->>API: 校验访客、员工启用、租户规则、日期/车辆
  API->>API: 继承被访人部门的拜访通行点
  API-->>FE: 创建成功，状态=待审核
  API->>SMS: 发送待审核提醒给被访人
  H->>API: 审核通过或拒绝
  alt 审核通过
    API->>API: 单次=待来访；多次=生效中；生成通行授权
    API->>SMS: 通知访客审核通过
  else 审核拒绝
    API->>API: 状态=审核失败，保存必填原因
    API->>SMS: 通知访客拒绝原因
  end
```

## 3. 被访人代申请与账号自动绑定

```mermaid
flowchart TD
  A[被访人填写访客手机号及申请] --> B{业务校验通过?}
  B -- 否 --> X[返回字段/规则错误]
  B -- 是 --> C{本租户存在该手机号访客账号?}
  C -- 是 --> D[绑定 visitorAccountId]
  C -- 否 --> E[accountBindingStatus=待绑定]
  D --> F{拜访形式}
  E --> F
  F -- 单次 --> G[直接生效：待来访]
  F -- 多次 --> H[直接生效：生效中]
  G --> I[生成授权并发送短信]
  H --> I
  J[访客以后用同手机号注册] --> K[后端查找待绑定申请]
  K --> L[自动补绑账号ID]
  L --> M[历史申请与通行事件保持不变]
```

代申请无访客确认节点。首次通行前允许发起人撤销；长期拜访允许提前终止剩余授权。

## 4. 扫码进入与离开

```mermaid
sequenceDiagram
  participant D as 扫码设备
  participant API as 后端
  participant A as 申请/授权
  participant X as 通行事件
  D->>API: 二维码 + deviceCode + direction + requestId
  API->>API: 校验设备绑定、启用、在线、租户和通行点
  API->>A: 校验码类型、有效期、使用次数、当前状态、授权通行点
  alt 核验成功
    API->>X: 新增一条进入或离开事件
    API->>A: 原子更新申请/访问批次状态
    API-->>D: 成功 + 访客最小展示信息
  else 核验失败
    API->>X: 可选记录失败核验日志，不写成功通行事件
    API-->>D: 失败原因（过期/已用/无权限/设备异常）
  end
```

## 5. 撤销与提前终止

```mermaid
flowchart LR
  A[代申请] --> B{是否已首次通行?}
  B -- 否 --> C[发起人申请撤销]
  B -- 是 --> D[不允许撤销]
  C --> E[服务端校验当前状态]
  E --> F[状态=已撤销]
  F --> G[所有未用二维码/授权作废]
  G --> H[保留申请与审计记录并短信通知]
  I[长期拜访生效中] --> J[发起人提前终止]
  J --> K[状态=已终止]
  K --> L[剩余授权作废，历史通行保留]
```

## 6. 短信可靠性

业务事务先提交，短信采用事务消息/Outbox 异步发送。短信失败不得回滚已成功的申请或审核，只更新发送记录为失败并支持后台追溯；自动重试次数和服务商待评审确认。
