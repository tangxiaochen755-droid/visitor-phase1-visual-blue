# 访客标品设计规范与语义 Tokens

版本：V1.0  
基线：线上 `ead78c4`  
适用：访客/被访人 H5、租户后台、超级管理后台、扫码设备端

## 1. 使用顺序

1. 先遵守业务信息架构与 `docs/DECISIONS.md`，再套用视觉 tokens。
2. 默认面向中国大陆企业用户，移动端遵守 `CHINA_PRODUCT_UI.md`。
3. 语义优先：组件引用 `brand / text / surface / border / status`，禁止直接按“浅蓝 1、灰 2”命名。
4. 新框架实现时使用 `design-tokens/semantic-tokens.json`；静态 CSS 或低成本迁移使用 `semantic-tokens.css`。

## 2. 核心组件映射

| 组件 | 语义规格 |
|---|---|
| H5 页面 | 最大宽 430px，左右 16px，底部和顶部适配 safe area |
| H5 输入框 | 48px 视觉高，16px 输入文字，6px 圆角，聚焦使用品牌色边框和浅色 focus ring |
| H5 触控区 | 不低于 44×44px；图标小于 24px 时仍保留完整触控盒 |
| H5 状态 Tab | 15px，44px 触控高，选中品牌色与统一短下划线 |
| H5 筛选 | 搜索和高频状态外露；日期、类型等进入不高于约 60% 视口的 Bottom Sheet |
| H5 卡片 | 白色 panel、8px 圆角、16px 内边距、弱边框和轻阴影 |
| 后台壳层 | 220px 侧栏、64px 顶栏、20px 内容边距 |
| 后台控件 | 36px 高、6px 圆角；表格行约 48px，表头约 42px |
| 后台弹窗 | 10px 圆角，头尾固定、内容滚动；敏感密钥不得明文回显 |
| 状态标签 | 12px，最小 24px 高；必须同时有文字，不以颜色单独表达状态 |

## 3. 状态语义

| 语义 | 用途 | 禁止用法 |
|---|---|---|
| info | 待来访、普通提示、当前选择 | 不代表成功结束 |
| success | 来访中、发送成功、启用 | 不用于待处理 |
| warning | 待审核、临期、需关注 | 不用于已拒绝 |
| danger | 审核拒绝、发送失败、破坏性确认 | 不滥用于普通提醒 |
| neutral | 已过期、来访结束、次级信息 | 不用于可操作主状态 |

审核状态和来访状态是两套业务字段；颜色 tokens 只负责视觉，不得合并状态口径。移动端申请卡片按 `DEC-014` 只展示当前主状态，详情与后台仍分别展示两套状态。

## 4. 响应式验收

- H5：390×844、430×932。
- 后台：1366×768、1440×900。
- 检查默认、空态、长文本、错误、禁用、加载、弹窗和最大数据量。
- 表格允许明确的横向滚动，但操作文字不得拆行；H5 不得出现页面级横向滚动。

## 5. 后续改动标记

以下内容尚未落入生产组件库，Cursor 开发时应保留为显式技术任务：

- 将当前 HTML 内重复 CSS 收敛为真实组件和 tokens 引用，迁移时必须逐页视觉回归，不能机械删除旧样式层。
- Remix Icon 字体存在客户端渲染风险，后续可迁移为本地 SVG 组件；本阶段不得随意替换造成图标语义变化。
- 语义 tokens 当前是交付基线，不代表已建立 Figma Variables 或跨端自动同步流水线。
