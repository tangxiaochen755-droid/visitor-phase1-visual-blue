# 访客标品最新产品逻辑测试基线

版本：V1.0
冻结日期：2026-09-11
适用范围：访客一期标品，不含华纳访客；扫码设备端本轮暂缓测试

## 1. 基线判定原则

- “最新”按已确认决策的生效日期与覆盖关系判定，不按文件名中的“当前版本”“V0.2”等字样判定。
- 当前有效口径以 `docs/DECISIONS.md` 中生效决策为最高依据；同级内容以日期较晚、范围更具体的决策覆盖较早内容。
- 当前浅蓝版页面、`docs/integration/` 和 `docs/研发交付简版.md` 用于验证决策是否已落到交付范围。
- 仓库外 XLSX、DOCX、早期产品说明书和历史黑白原型只用于查漏；与生效决策冲突时，冲突内容不得进入实现和测试。
- `FUTURE-01` 至 `FUTURE-07` 仍未冻结，不得把建议方案当成现行产品逻辑。

## 2. 当前有效核心流程

| 流程 | 当前有效逻辑 | 关键依据 | 必须排除的旧逻辑 |
|---|---|---|---|
| 企业与身份 | 一企业一租户，租户数据隔离；被访人与访客身份互斥 | DEC-001 | 跨租户查询、同一企业身份混用 |
| 访客自主申请 | 提交后进入待审核；审核通过后进入待来访，拒绝时来访状态为空 | DEC-012 | 用一个混合状态表达审核和来访阶段 |
| 被访人审核 | 支持单条通过/拒绝和批量通过/拒绝；批量拒绝使用统一原因，服务端逐条返回结果 | DEC-011、DEC-012 | 批量请求整体成败、同批逐条填写不同拒绝原因 |
| 被访人代申请 | 提交后直接生成有效申请；按本租户手机号绑定，未注册时待绑定，注册后自动补绑 | DEC-002 | 待访客确认、确认/拒绝邀请、重发邀请、邀请有效期、二次审批 |
| 申请与访问记录 | 一条申请可关联多条进入/离开明细；申请详情展示完整通行时间轴 | DEC-003 | 将申请记录与单次进出记录混为一条数据 |
| 拜访形式 | 用户文案为“单次拜访/长期拜访”；内部可保留 `MULTIPLE` 枚举 | DEC-007 | 面向用户继续显示“多次拜访” |
| 来访目的 | 租户配置目的；“其他”为系统保留项且必须填写详情；历史保存名称快照 | DEC-008 | 历史记录随配置改名/删除而改变 |
| 来访日期与时段 | 后台统一配置时段；单次单选、长期多选；日期/有效期、时段、被访人固定必填 | DEC-013 | 前台任意输入时段、长期仅能选一个时段 |
| 双状态 | 审核状态：待审核/审核通过/审核拒绝；来访状态：待来访/来访中/已过期/来访结束/已终止；待审核或拒绝时来访状态为空 | DEC-012 | “生效中”“审核失败”“已失效”“已结束”等混合大状态 |
| 移动端状态展示 | 申请卡片只显示当前主状态；详情和后台仍分别保留并展示双状态 | DEC-014 | 卡片并列两组状态标签，或详情丢失双状态 |
| 单次结束 | 来访中可扫码出访结束；预约结束时间到达后系统自动结束，并区分结束原因 | DEC-010 | 超时后仍保持来访中、重复生成结束记录 |
| 长期循环与终止 | 每次离场后恢复待来访；授权期结束为已过期；在场时终止先置 `terminationPending=true`、禁入但允许当前出访，出访后转已终止 | DEC-010、DEC-012 | 把 `terminationPending` 当状态枚举、在场时立即终止且无法出访 |
| 租户开户与登录 | 开户保留唯一企业管理员账号、手工初始密码及登录方式；开户后登录方式不可修改，可重置管理员密码 | TASK-009 | 租户后台自行改登录方式、生成多个初始管理员 |
| 短信渠道 | 新租户默认平台短信；开户后通过独立短信配置切换自有企信通及模板 | DEC-015 | 在新增租户表单选择短信渠道、密钥明文回显或入日志 |
| 企业前台入口 | 仅 `frontends/enterprise-h5.html` 为当前入口，按身份展示访客/被访人能力 | DEC-016 | 从历史 `visitor-h5.html`、`visitee-h5.html` 复制或交付旧逻辑 |
| 角色权限 | 企业管理员写权限已确认；部门负责人、场所管理员写权限未冻结，默认不得推导放权 | TASK-012、FUTURE-02 | 因能看到数据就默认拥有审核、代申请、撤销或终止权限 |

## 4. 测试执行要求

- 测试清单必须同时验证“当前流程能完成”和“被废止流程不存在”。
- 遇到页面、接口、数据库或文档口径冲突时暂停该用例，以本文件和对应 DEC 编号提产品确认，不得自行兼容两套流程。
- 缺陷单必须写明命中的决策编号、构建 SHA、请求与响应、数据状态及复现时间。
- 本基线配套执行 `docs/代码测试清单.md`；扫码设备端条目保留但本轮不计入执行总数。
