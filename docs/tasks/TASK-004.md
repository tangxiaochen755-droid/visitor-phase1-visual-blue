# TASK-004 — 拜访类型、目的配置与审核记录优化

- 状态：已完成（已发布）
- 日期：2026-08-12
- 负责人：Codex

## 范围

- 将一期“多次拜访”产品文案全局调整为“长期拜访”。
- 租户后台增加来访目的配置，支持新增、改名、启停和删除。
- 前台选择“其他”目的时增加具体目的必填输入。
- 访客和被访人申请记录强化代申请提醒；被访人端增加待审核默认态、批量审核、标签数量与拜访形式筛选。
- 同步需求基线、研发对接文档、决策和变更日志。

## 排除项

- 保持内部原型变量 `multiple` 和建议接口枚举 `MULTIPLE` 不变，避免文案调整被误解为数据迁移。
- 不修改黑白交互原型仓库。
- 未经用户明确要求，本任务不发布线上。

## 验收标准

- 仓库用户可见文案不再出现“多次拜访”。
- 来访目的配置可完成增删改和启停，名称空值/重复有校验，“其他”不可删除。
- 前台选择“其他”后显示具体目的输入，空值不可提交。
- 被访人进入申请记录默认显示待审核；批量审核按进入多选、勾选、二次确认、批量处理执行。
- 申请状态标签显示数量，单次/长期筛选可组合使用。
- 代申请记录存在明显、非仅靠颜色的文字标识。
- 申请记录常驻筛选仅保留搜索和状态 Tab，日期与拜访形式进入不超过 60% 视口的底部筛选面板。
