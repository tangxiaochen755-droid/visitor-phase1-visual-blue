# TASK-023 — 收口员工注册字段与审核状态

## 范围

- 员工注册入口统一命名为“员工注册”，说明统一为“审核通过后可作为被访人使用”。
- 移除员工工号字段。
- 所属部门由员工手工填写，不在公开注册页展示企业部门选项。
- 企业后台审核时确认员工对应的企业正式部门。
- 注册状态统一为待审核、审核通过、审核拒绝，并与账号启用、禁用状态分开记录。
- 同步产品决策、接口契约、联调验收、测试清单和功能映射文档。

## 排除项

- 不改变访客注册、代申请待绑定及注册后自动补绑逻辑。
- 不改变后台单个新增和批量导入员工能力。
- 不推送、不发布，除非用户另行确认。

## 验收标准

- 员工注册页不出现员工工号和部门下拉框。
- 所属部门为必填文本输入，未填写时阻止提交。
- 页面标题及入口统一显示“员工注册”。
- 后台待审核员工可由有权限账号确认正式部门后通过，或填写原因后拒绝。
- 注册状态与账号状态分别展示；通过后生成身份编码并启用，拒绝后保持未启用。
- 文档中不再将员工工号作为员工自注册条件，不再使用“待认证”作为当前注册状态。

- 已完成。

- 企业后台员工列表已核对：注册状态与账号状态分列展示。
- 员工注册审核弹窗已核对：展示员工填写的所属部门，由审核人确认正式部门；审核通过后生成身份编码并启用账号。
