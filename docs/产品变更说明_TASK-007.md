# 产品变更说明：时段、双状态与设备模型

## 产品规则

1. 后台维护统一的预约时段。单次拜访选择一个时段，长期拜访在有效期内选择一个或多个时段。
2. 来访日期（长期为开始/结束日期）、来访时段、被访人为系统固定必填字段，租户不可关闭显示或取消必填。
3. 申请同时保存审核状态和来访状态。审核未完成或被拒绝时，来访状态为空；审核通过后才进入来访生命周期。
4. 长期拜访不再用“生效中”作为前台大状态：当前无在场批次时为待来访，有未闭合批次时为来访中。
5. 来访码和出访码必须展示授权生效期、当前码有效期限；具体签名和刷新机制由研发方案确定。
6. 设备类型一期仅包含扫码设备、扫码中台。设备可先建档为未绑定，后续再绑定场所和通行点。

## 页面承接

| 页面 | 调整 |
| --- | --- |
| 租户后台 / 拜访设置 | 时段配置说明覆盖单次和长期；必填字段锁定 |
| 前台 / 申请访问 | 长期有效期 + 多时段选择；必填校验 |
| 前台 / 申请记录 | 审核状态主筛选；来访状态、拜访形式、来访日期范围进入筛选弹层 |
| 租户后台 / 申请记录 | 审核状态、来访状态分列与独立筛选 |
| 通行码展示 | 增加授权生效期、二维码有效期限 |
| 租户后台 / 场所设备 | 增加设备类型；场所和通行点允许未绑定 |

## UI Project 交接

- 移动端保持搜索框 + 审核状态 Tab 两行常驻结构。
- 来访状态属于次筛选，不增加第三行常驻筛选。
- 双状态在记录卡内以“审核：…”和“来访：…”并列短标签展示，避免只显示一个含混状态。
- 后台采用紧凑筛选表单与横向可滚动表格，不牺牲字段完整性。
